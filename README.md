# KVS Job для MAX

KVS Job — мини-приложение и чат-бот MAX для студентов Финансового университета. Сервис показывает вакансии и стажировки партнёров, позволяет сохранять интересные предложения, узнавать о мероприятиях и регистрироваться на них. Карьерный центр управляет мероприятиями и обновляет каталог вакансий из Google Таблицы.

## Основной пользовательский сценарий

1. Студент открывает Mini App из чат-бота MAX (либо локально для технической проверки).
2. Ищет вакансию по названию и фильтрам, открывает карточку и переходит на страницу работодателя.
3. В разделе «Профиль» вводит почту вида `name@edu.fa.ru`.
4. Добавляет вакансию в избранное, открывает вкладку «Избранное».
5. Открывает «Мероприятия», регистрируется и после регистрации переходит в чат мероприятия.

До ввода почты избранное пусто и добавление недоступно. Оно привязано к введённому email в конкретном MAX WebView/браузере, поэтому не является общим для всех пользователей.

## Состав и архитектура

```text
MAX Bot ────────────────┐
                         ├── Python: bot + FastAPI + Mini App ── PostgreSQL
MAX WebView / браузер ──┘                   │
                                            └── Google Sheets API
```

- `main.py` — запуск чат-бота MAX, FastAPI и фоновых задач;
- `miniapp/app.py` — REST API и раздача Mini App;
- `miniapp/static/` — клиент Mini App;
- `database/` — модели и идемпотентная инициализация PostgreSQL;
- `miniapp/services/vacancy_sheet.py`, `services/google_sheets.py` — импорт вакансий;
- `services/vacancy_scheduler.py` — синхронизация по расписанию;
- `docker-compose.yml` — контейнеры приложения и PostgreSQL.

При старте приложение ждёт PostgreSQL и создаёт недостающие таблицы. Повторный запуск не удаляет существующие данные.

## Запуск всех локальных компонентов

Требования: Docker Desktop с Docker Compose и свободные порты `8000` и `15432`.

1. Создайте `.env` рядом с `docker-compose.yml`, взяв за основу `.env.example`.
2. Выполните единственную команду запуска:

```powershell
docker compose up --build
```

Команда запускает одновременно приложение и PostgreSQL. После запуска откройте <http://127.0.0.1:8000/miniapp>.

```powershell
docker compose ps
```

Ожидаемый статус: `bot — Up`, `postgres — Up (healthy)`.

## Переменные окружения

Секреты (`.env`, токен MAX, `credentials.json`) не добавляются в Git и архив сдачи.

| Переменная | Назначение | Значение для локальной проверки |
| --- | --- | --- |
| `MAX_BOT_TOKEN` | токен чат-бота MAX | можно оставить пустым, если проверяется localhost |
| `MAX_ADMIN_IDS` | ID администраторов MAX через запятую | необязательно |
| `MAX_API_BASE_URL` | API платформы MAX | значение из `.env.example` |
| `MAX_REQUIRED_CHANNEL_ID`, `MAX_REQUIRED_CHANNEL_URL` | проверка подписки | `0` и пустая строка отключают её |
| `ADMIN_EMAIL` | email доступа к админ-панели | `253103@edu.fa.ru` |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | учётные данные PostgreSQL | значения из примера |
| `DB_HOST`, `DB_PORT` | БД при запуске вне Docker | `localhost`, `15432` |
| `MINIAPP_ENABLED` | включает Mini App | `true` |
| `MINIAPP_HOST`, `MINIAPP_PORT` | адрес и порт FastAPI | `0.0.0.0`, `8000` |
| `MINIAPP_PUBLIC_URL` | публичный URL Mini App для MAX | localhost для Docker-проверки |
| `MINIAPP_DEV_ADMIN_ENABLED` | отладочный доступ администратора | `false` |
| `GOOGLE_SHEETS_URL` / `GOOGLE_SHEET_NAME` | источник вакансий | необязательно при локальной проверке |
| `GOOGLE_CREDENTIALS_FILE` | JSON сервисного аккаунта Google | `credentials.json` |
| `VACANCY_SYNC_SCHEDULE_ENABLED` | обновление по расписанию | `true` / `false` |
| `VACANCY_SYNC_HOUR`, `VACANCY_SYNC_MINUTE`, `VACANCY_SYNC_TIMEZONE` | время синхронизации | `0`, `0`, `Europe/Moscow` |
| `VACANCY_SYNC_ALLOW_EMPTY` | разрешить пустому источнику стереть каталог | рекомендуется `false` |
| `SEED_DEMO_DATA` | демонстрационные компании при чистой БД | `false`; включить `true` для демо |

Используемые порты:

- `8000` хоста → `8000` контейнера приложения — API и Mini App;
- `15432` хоста → `5432` контейнера PostgreSQL.

## Внешние сервисы и данные

### MAX

MAX предоставляет чат-бот и WebView. Docker не может воспроизвести этот внешний сервис. Чтобы проверить основной сценарий именно в MAX, необходимы:

1. созданный бот MAX и действующий `MAX_BOT_TOKEN`;
2. публичный **HTTPS** адрес в `MINIAPP_PUBLIC_URL` — localhost из MAX недоступен;
3. кнопка/ссылка бота на этот адрес.

После настройки приложение остаётся доступно пользователям внутри MAX; Docker используется для воспроизводимой локальной проверки.

### Google Sheets

Google Таблица — источник вакансий, PostgreSQL — рабочее хранилище, из которого Mini App получает каталог без ожидания Google API. Создайте сервисный аккаунт Google, положите ключ в `credentials.json`, предоставьте его email доступ «Читатель» к таблице и задайте `GOOGLE_SHEETS_URL`.

В первой строке таблицы должны быть заголовки. Поддерживаются поля:

`Организация`, `Подразделение`, `Вакансия`, `Сфера`, `ЗП`, `График`, `Формат`, `Описание`, `Формат трудоустройства`, `Особенность 1`, `Особенность 2`, `Особенность 3`, `Ссылка на вакансию`.

Импортируется строка с заполненными «Организация» и «Вакансия». Администратор запускает импорт кнопкой «Обновить вакансии из Google Таблицы». При ошибке источника или пустом ответе старый каталог сохраняется, если `VACANCY_SYNC_ALLOW_EMPTY=false`.

Мероприятия, регистрации, партнёры и вакансии хранятся в PostgreSQL. Избранное хранится локально для конкретного email пользователя.

## Тестовые данные

- База и обязательные партнёры создаются автоматически.
- Для демонстрационных компаний задайте `SEED_DEMO_DATA=true` до первого запуска на чистой БД.
- Для проверки импорта используйте копию Google Таблицы с двумя строками, содержащими «Организация» и «Вакансия».
- Полный сброс **локальных Docker-данных**: `docker compose down -v`, затем `docker compose up --build`. Команда удалит PostgreSQL-том проекта.

## Административная панель

```text
Email: 253103@edu.fa.ru
Пароль: не используется
```

Откройте «Профиль» → «Войти в профиль», введите email и откройте «Панель разработчика». В панели доступны мероприятия, партнёры, статистика и вкладка «Вакансии» с ручной синхронизацией Google Таблицы.

При создании мероприятия:

- «Категория» — группа фильтра, например `Хакатоны`, `Воркшопы`, `Дни карьеры`;
- «Точная дата и время» — время начала для регистрации и напоминаний;
- «Дата и время» — текст карточки, например `25 сентября, 18:00`;
- «Пояснение по регистрации» — текст над кнопкой, например `Регистрация до 20 сентября`;
- «Ссылка на чат мероприятия» доступна пользователю после регистрации кнопкой «Перейти в чат»;
- «Лимит участников» — число доступных мест; после заполнения новые пользователи попадают в резерв.

## Пошаговая проверка и ожидаемое поведение

1. Запустите `docker compose up --build`, затем `docker compose ps`.
   - Ожидается: `bot` слушает 8000, `postgres` — `healthy`.
2. Откройте `http://127.0.0.1:8000/miniapp`.
   - Ожидается: каталог открывается, загрузочный экран не остаётся навсегда.
3. Найдите вакансию, примените фильтр, откройте карточку и ссылку работодателя.
   - Ожидается: выдача меняется по фильтрам, ссылка открывается отдельно.
4. До входа нажмите сердце вакансии.
   - Ожидается: требуется ввод почты; заранее добавленных вакансий нет.
5. Войдите как `student1@edu.fa.ru`, добавьте вакансию, затем смените email на `student2@edu.fa.ru`.
   - Ожидается: у первого пользователя вакансия есть, у второго список пуст; активное сердце красное и не дублируется.
6. Откройте «Мероприятия» и зарегистрируйтесь.
   - Ожидается: пояснение срока размещено над кнопкой, после регистрации появляется «Перейти в чат».
7. Войдите администратором, создайте мероприятие с лимитом и отредактируйте его.
   - Ожидается: лимит не сбрасывается; подсказка о категории видна в узком окне MAX.
8. При настроенных Google credentials измените тестовую строку и нажмите кнопку синхронизации.
   - Ожидается: каталог обновляется без перезапуска; ошибка Google не удаляет старые вакансии.

## Зависимости

Python 3.12, PostgreSQL 15, Docker Desktop. Python-зависимости перечислены в `requirements.txt`: FastAPI/Uvicorn, SQLAlchemy/asyncpg, gspread и Google Auth, python-dotenv, Pillow. Node.js не требуется.

## Известные ограничения MVP

- Вход по email — демонстрационный механизм; для production нужен серверный RBAC и подтверждённая авторизация MAX.
- Избранное не синхронизируется между устройствами.
- MAX требует реальный токен, публичный HTTPS и настройку бота; Docker не эмулирует платформу.
- Импорт зависит от доступности Google Sheets и прав сервисного аккаунта.
- Для компаний без подтверждённого локального логотипа показываются инициалы, а не сгенерированная иконка.
