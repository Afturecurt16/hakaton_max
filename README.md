# KVS Job — мини-приложение для MAX

KVS Job показывает студентам Финансового университета вакансии, компании-партнёры и карьерные мероприятия. Интерфейс открывается в MAX как Mini App по HTTPS-ссылке; для локальной проверки его можно открыть в обычном браузере. Проект запускается одним сервисом FastAPI и PostgreSQL. Имя сервиса `bot` в Docker Compose сохранено, но `main.py` запускает веб-приложение, а не отдельный процесс рассылки в чат MAX.

## Что работает сейчас

- Вакансии загружаются из PostgreSQL, куда их можно импортировать из Google Таблицы вручную из панели разработчика или по расписанию. Избранное хранится в браузере отдельно для каждой введённой почты.
- Партнёры и подразделения показываются из PostgreSQL. У подразделений нет искусственных иконок; исправления изображений вакансий будут внесены отдельно.
- Мероприятия создаются в панели разработчика. Студент с почтой `@edu.fa.ru` может зарегистрироваться, попасть в основной список или резерв и открыть ссылку на чат мероприятия, если она задана.
- Сообщения организатора, подтверждения регистрации и перевод из резерва поступают в раздел «Уведомления» самого Mini App, а не в личный чат MAX. Колокольчик показывает число непрочитанных; открытие раздела помечает сообщения прочитанными. Автоматическая отправка напоминаний пока не подключена к запуску приложения.
- В профиле после входа заполнена только почта. Факультет, курс и группу студент указывает и редактирует сам; эти поля сохраняются в PostgreSQL и доступны при повторном входе с той же почтой.

Вход по почте сейчас упрощённый: владение адресом не подтверждается. Поэтому это **не production-авторизация** и не защита персональных данных. Перед публичным использованием нужны подтверждение почты или надёжная авторизация через MAX, а также серверная проверка прав разработчика.

## Состав проекта

| Путь | Назначение |
| --- | --- |
| `main.py`, `miniapp/app.py` | FastAPI, REST API и раздача Mini App |
| `miniapp/static/` | интерфейс без сборки Node.js |
| `database/` | модели и подготовка схемы PostgreSQL при запуске |
| `services/vacancy_scheduler.py` | фоновая синхронизация вакансий |
| `services/event_reminder_scheduler.py` | заготовка фоновых напоминаний; пока не подключена к запуску |
| `services/max_bot.py` | обращения к API MAX, например проверка подписки при её включении |
| `docker-compose.yml` | сервисы `bot` и `postgres` |

База создаётся и проверяется при запуске контейнера. Логи показывают, сколько заняла подготовка БД. Повторный запуск не удаляет записи; данные PostgreSQL лежат в Docker volume `postgres_data`.

## Первый локальный запуск

Нужны Docker и Docker Compose. Из корня проекта:

```bash
cp .env.example .env
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 bot
```

На Windows файл `.env` можно скопировать командой `Copy-Item .env.example .env`. По умолчанию Mini App доступно по адресу <http://127.0.0.1:8000/miniapp>, проверка сервера — <http://127.0.0.1:8000/healthz>, PostgreSQL с хоста — порт `15432`. Для страницы `/miniapp` используйте GET (`curl -i`), а не `curl -I`: HEAD может возвращать 405.

Для локального запуска Python с PostgreSQL в Docker также есть `start-local.ps1`. Он использует виртуальное окружение в родительской папке проекта.

## Обновление уже работающего сервера

Сначала отправьте изменения в ветку `miniapp`, затем в каталоге проекта на сервере:

```bash
git pull --ff-only origin miniapp
docker compose up -d --build bot
docker compose ps
docker compose logs --tail=100 bot
```

Эта команда пересобирает приложение и не удаляет том PostgreSQL. **Не используйте `docker compose down -v` для обновления**: ключ `-v` удаляет данные. Если на сервере приложение слушает порт `8001`, сохраните `MINIAPP_PORT=8001` в серверном `.env`; Nginx для этого домена должен проксировать на `127.0.0.1:8001`. Другие проекты и их конфигурации менять не требуется. Подробности публикации — в [SERVER_DEPLOY.md](SERVER_DEPLOY.md).

## Настройки

Все переменные перечислены в [.env.example](.env.example). Основные:

| Переменная | Для чего |
| --- | --- |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | доступ к PostgreSQL |
| `MINIAPP_PORT`, `MINIAPP_PUBLIC_URL` | локальный порт и публичный HTTPS-адрес Mini App |
| `MAX_BOT_TOKEN` | токен для API MAX; локальный просмотр без интеграции возможен и без него |
| `MAX_REQUIRED_CHANNEL_ID`, `MAX_REQUIRED_CHANNEL_URL` | обязательная подписка; `0` отключает проверку |
| `ADMIN_EMAIL` | почта, открывающая панель разработчика в текущей демоверсии |
| `GOOGLE_SHEETS_URL`, `GOOGLE_CREDENTIALS_FILE` | импорт вакансий из Google Таблицы |
| `VACANCY_SYNC_SCHEDULE_ENABLED`, `VACANCY_SYNC_HOUR`, `VACANCY_SYNC_MINUTE` | обновление вакансий по расписанию |
| `SEED_DEMO_DATA` | добавить демонстрационные компании при пустой БД; по умолчанию `false` |

Не добавляйте `.env`, `credentials.json`, токены и дампы БД в Git. Для работы через MAX нужен публичный HTTPS-адрес, настроенная кнопка Mini App у бота и соответствующий `MINIAPP_PUBLIC_URL`. Docker сам по себе не эмулирует MAX.

## Данные и проверка сценариев

Администратор открывает «Профиль» под адресом из `ADMIN_EMAIL` и переходит в «Панель разработчика». Там можно создавать мероприятия, управлять партнёрами, смотреть статистику и запускать импорт вакансий. Ссылка на чат мероприятия — отдельное поле события: уведомления всё равно остаются внутри Mini App.

После входа студента проверьте следующее:

1. В профиле видна почта, а факультет, курс и группа изначально пустые. Заполните их, сохраните и повторно откройте профиль.
2. Добавьте вакансию в избранное и убедитесь, что после выхода с этой почты избранное другого адреса пустое.
3. Зарегистрируйтесь на мероприятие. Откройте колокольчик: сообщение о регистрации должно быть там, а число непрочитанных после просмотра — уменьшиться.
4. Откройте партнёра и его подразделение: карточки подразделений без искусственных буквенных иконок.

Если Google Таблица подключена, сервисный аккаунт должен иметь к ней доступ. Мини-приложение читает вакансии из PostgreSQL и не ждёт ответа Google при каждом открытии страницы. При ошибке импорта прежний каталог сохраняется, если `VACANCY_SYNC_ALLOW_EMPTY=false`.

## Диагностика

```bash
docker compose ps
docker compose logs --tail=200 bot
curl -sS -i http://127.0.0.1:8000/healthz
curl -sS -i http://127.0.0.1:8000/api/v1/events
```

Замените `8000` на значение `MINIAPP_PORT` вашего сервера. Если локальный API отвечает, а публичный домен выдаёт 502, проверьте прокси именно этого домена и его порт. Остановка с сохранением данных: `docker compose down`.
